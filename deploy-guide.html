上线实操 · 指南

从 HTML 原型到微信小程序真正卡住你的不是技术，是主体和备案

这一页把「怎么部署到微信开发者平台」拆成可执行的步骤。但先要拦住两个最常见的误解： ① HTML 原型不能直接上传，小程序是 WXML/WXSS/JS 的独立体系；② 决定你能不能上线的第一件事不是代码，而是你用什么主体注册——主体类型直接决定了哪些类目能做、能不能收钱。

先认清：HTML 原型 ≠ 小程序工程

这两件事的差别，决定了你必须选一条路线，没有「直接上传」这个选项。

维度现在的 HTML 原型微信小程序
页面结构HTML 标签（div / span / svg）WXML：用 view / text / image 等组件书写
样式CSS，可用任意选择器WXSS：接近 CSS，但选择器与单位受限（推荐 rpx）
逻辑浏览器 JS，可直接操作 DOM小程序 JS，没有 DOM，靠数据驱动视图更新
运行环境浏览器微信客户端内的 JavaScript 引擎（双线程模型）
能否直接上传不能。必须按小程序的四类文件（wxml / wxss / js / json）重新组织，逐屏翻译。

三条技术路线，先选一条

路线 A · 手工转小程序

做法：在微信开发者工具里新建项目，把 7 屏逐屏翻译成 WXML/WXSS，交互改成数据驱动的写法。

优点：最标准，审核最顺，性能最好。

代价：工作量最大，HTML/CSS 里那些精心的排版要重新写一遍。

路线 B · 先做成 H5 建议先走

做法：现有原型原封不动部署到静态托管（如 GitHub Pages / 云静态托管），微信里就能打开链接。

优点：零备案门槛、当天可完成，演示、投递、收反馈全都够用。

代价：不是小程序，不能出现在微信搜索、不能用小程序码。但作为「先验证再上线」的第一步性价比最高。

路线 C · 跨端框架

做法：用 uni-app / Taro 等框架写一套代码，同时编译出 H5 和小程序。

优点：一次开发两端产出，后期想上其他平台也方便。

代价：要额外学框架与其编译规则，出问题时排查链条更长。

建议的顺序：B → A（或 B → C）。先用路线 B 把原型变成「能发出去的链接」，本周就能拿到反馈； 等要真正上架时再走路线 A 做小程序版。不要一上手就啃小程序语法——那会把你卡在语法细节里，拿不到任何人的反馈。

主体类型决定生死

这一节比后面所有步骤加起来都重要，请先读完再动手注册。

⚠️ 你的项目按现方案做，个人主体大概率过不了审

原因很直接：方案里的两个核心模块正好踩在个人主体的禁区上—— 「服务预约」（商家入驻、服务撮合） 属于经营性功能， 「社区广场」（用户发帖互动） 属于社交类目。 平台规则是「个人主体不得从事经营性活动」，这两块都会被判为 「超出个人主体范围」而驳回。

个人主体自身的能力也很受限：不能开通微信支付、不能申请微信认证、可选服务类目只集中在 「工具 / 简单查询预约 / 资讯 / 个人创作 / 兴趣爱好」这几类，且不支持「附近的小程序」。

2.1　个人 vs 企业（含个体工商户）对照

对比项个人主体企业 / 个体工商户
微信支付不可开通可开通，支持商户号
服务类目范围仅工具、简单查询预约、资讯、个人创作等少数类目几乎全类目（特殊行业另需资质）
社交 / 社区功能不开放可申请，需配内容安全与举报机制
微信认证无法申请（因此拿不到认证标识与部分能力）可申请，约 300 元/年
备案数量上限5 个50 个
搜索权重 / 附近的小程序默认较低 / 不支持更高 / 支持 LBS 展示
适合做什么工具、查询、个人作品展示、博客涉及交易、预约、社交、入驻、课程的场景

2.2　给你的判定

你的功能模块主体要求结论
文化科普（是什么 / 时间轴 / 图鉴 / 三地差异）个人可做纯内容展示，可归入「文化娱乐-个人创作」或「资讯」类
七步仪式互动 + 知识闯关个人可做属于工具/互动玩法，不含交易
祝福卡生成 + 分享个人可做只要不做诱导分享（如「不转发不能生成」），就没问题
服务预约（商家入驻、撮合）需企业 / 个体户经营性 + 第三方入驻平台模式，另外可能还需增值电信业务许可
社区广场（UGC 发帖互动）需企业 / 个体户社交类目个人不开放；且必须接入内容安全检测与举报入口
研学 / 教育内容（如面向学校）谨慎教育培训类目对个人不开放，且可能需办学相关资质，建议先按「文化科普」定位
结论：如果只是参赛 / 作品集 / 演示，走路线 B（H5）完全够，不需要注册小程序、不需要备案，零门槛。 如果是真想上线运营，最省事的路径是注册个体工商户（线上政务平台一般 3–5 个工作日出证，成本很低，无需会计代账）， 再把小程序主体设为个体工商户——之后微信支付、全类目、认证都能解锁。

上线九步

分三条轨道推进，其中备案与开发可以并行，别串行等。

图 1　三轨路线图：轨道 A（注册 → 备案 → 类目）与轨道 B（开发 → 上传）可并行推进，别串行等； 轨道 C 必须在 A 的备案通过后才有意义——没有备案号，代码提交审核这一步根本走不到。

每步要点速查

#步骤要点与常见坑
1注册账号在微信公众平台注册，邮箱不能是已注册过公众号/开放平台的邮箱。主体类型一旦选定很难改，先想清楚。
2完善信息 / 取 AppID填写名称、头像、简介、服务范围。AppID 在「开发设置」里，填进开发者工具才能真机预览与上传。
3小程序备案2026 年最硬的一道关。入口在「设置 → 小程序备案 → 新增备案」。需主体信息、负责人信息、人脸核身、短信核验。未备案无法提交审核、无法被搜索。
4服务类目类目必须与「主体性质」和「实际功能」同时匹配，选错必被驳回。不确定时按最保守的那个功能去选。
5安装开发者工具微信官方「微信开发者工具」，下载即用。需用管理员/开发者微信扫码登录。
6新建项目选「小程序」，填 AppID，选不使用云开发（或按需）。项目结构由工具自动生成。
7开发与调试四个核心位置：app.json 管页面注册与底部 tabBar，pages/ 放页面，app.wxss 放全局样式，app.js 放全局逻辑。没有 DOM，一切靠 setData 驱动视图。
8上传代码点「上传」，填版本号（如 1.0.0）与备注。单个代码包上限 2MB，图片多的话要放 CDN 或做分包。
9隐私保护指引只要调用了位置、手机号等隐私接口，就必须在指引里声明使用场景，并在代码里做授权适配，否则会被「未声明隐私接口」直接驳回。
10提交审核在「版本管理」提交，填写功能页面路径、服务类目、预览截图；如功能需登录，要提供测试账号给审核人员。
11发布上线审核通过后点「全量发布」。之后改文案/图片一般无需重新提审；改逻辑或结构必须重新走审核。

七个最容易卡住的点

按「卡住概率 × 排查难度」排序。前三个是硬门槛，后面的都是驳回高发区。

  • 小程序备案没做。2026 年这是强制前置条件，未备案的小程序无法发布、无法被搜索访问。入口在后台「设置 → 小程序备案」。平台初审约 1–2 个工作日，属地通信管理局终审约 1–20 个工作日（各地差异大）。备案期间不要更换负责人或手机号，否则核验失效、需要撤回重提。
  • 主体类型选错。个人主体做不了社交、入驻、交易类功能，也开不了微信支付。这一条是后面所有驳回的根源，注册前就要定。
  • 服务类目与实际功能不匹配。驳回原因里最高频的一类。选择时遵循两条：与主体性质匹配、与实际运营匹配。不要为了绕审核去选宽泛类目，平台一眼能看出来。
  • 后端域名不合规。只要小程序要调你自己的接口，该域名必须：已完成 ICP 备案 + 使用 HTTPS + SSL 证书链完整（含中间证书）+ 在小程序后台「开发设置 → 服务器域名」加入白名单。四个条件缺一个，接口就全部调不通。开发阶段可以先在开发者工具里勾「不校验合法域名」绕过，但那只对本地调试有效。
  • 隐私接口未声明。调用了获取位置、手机号等能力，却没有在《用户隐私保护指引》里声明使用场景，会被直接驳回。本项目核心用户是 15 岁左右青少年，收集任何个人信息都要写清用途，并建议明确告知监护人同意机制。
  • UGC 社区没做内容安全。只要开放用户发帖，就必须接入内容安全检测、提供举报入口、公示用户协议与社区公约。这是社交功能审核的硬要求，也是最容易被打回的一块。建议 MVP 阶段直接不做社区。
  • 代码包超过 2MB。单个代码包上限 2MB。本项目图鉴、祝福卡背景图这类资源较多，建议图片全部走对象存储/CDN，或使用分包加载。
还有两个「软坑」： ① 诱导分享——「邀请 N 位好友才能解锁证书」这类设计很容易被判违规，建议改成「邀请后获得额外样式」而非「不邀请就不给」； ② 非遗名称使用——对外的「省级非遗」表述要客观陈述（如「依据 2018 年广东省省级非遗名录」）， 不能暗示官方背书，也不能把非遗名号用于商业宣传。

本项目分阶段落地建议

不要想一次做完整版再上线。把「能过审」和「功能完整」分开。

阶段形态做什么目的与门槛
阶段 1
本周可完成		 H5（路线 B） 把现有 4 个 HTML 直接部署到静态托管，得到一个可访问的链接，微信里能打开。 目的：演示、投递、收反馈。
门槛：零备案、零注册。
阶段 2
MVP 过审版		 小程序
（3 页）		 只做「首页 + 出花园是什么 + 祝福卡生成」三页，纯静态内容、不接后端、不做社区与预约。类目按「文化娱乐-个人创作」或「生活服务-兴趣爱好」定位。 目的：跑通「注册 → 备案 → 上传 → 审核 → 发布」全流程。
这是过审概率最高的形态。
阶段 3
服务闭环		 小程序
+ 后端		 加预约服务与商家展示（先只展示、不做线上支付），接后端接口。 门槛升级：主体需为个体工商户/企业；域名需 ICP 备案 + HTTPS。
若走「商家入驻平台」模式，可能还需增值电信业务许可。
阶段 4
社区与运营		 完整版 开放社区广场（UGC）、纪念证书、活动报名，配内容安全与审核机制。 门槛：内容安全接口 + 举报入口 + 用户协议齐备，审核会重点看这一块。
关键提醒：阶段 2 的「三页静态版」不只是练兵——它就是你的最小可上线产品。 平台审核对「功能简单但闭环完整」的小程序最友好。先把这三页发出去，比憋一个做完不缺但永远上不了线的完整版有价值得多。

成本与周期

先看钱，再看时间——你会发现「先做 H5」几乎不要钱。

6.1　费用

项目费用说明
小程序账号注册免费个人与企业主体注册本身均不收费
个体工商户执照基本免费线上政务平台申请，一般 3–5 个工作日出证，无需会计代账
微信认证约 300 元/年企业/个体工商户认证费用（多来源一致）。个人主体能否认证以后台实际显示为准（不同资料说法有出入）
小程序备案免费但需投入时间等待审核
域名约 30–60 元/年仅在需要自建后端接口时才需要
域名 ICP 备案免费由云服务商代办，需数日至数周
静态托管（H5）接近 0 元GitHub Pages、各家云静态托管均有免费额度
服务器 / 后端约 100–300 元/年起MVP 阶段若纯静态内容，完全可以先不买
结论：如果目标是参赛 / 作品集（阶段 1），成本是 0 元。 如果要真正上线含预约与社区（阶段 3–4），主要成本是营业执照 + 微信认证 + 域名 + 可能的经营许可办理时间，其中「时间」比「钱」更需要提前规划。

6.2　周期（材料零失误的理想情况）

环节参考周期能否并行
注册账号 + 完善信息0.5–1 个工作日—
个体工商户执照（如需）3–5 个工作日可与设计/开发并行
小程序备案1–20 个工作日（各地差异大）可与开发并行，是最值得提前启动的一步
开发（三页 MVP）视熟练度，1–2 周与备案并行
代码审核1–7 个工作日—
合计（顺利）约 2–4 周备案与开发同时做，可显著压缩
务必留缓冲：备案的管局终审时长不可控（不同省份差异极大）， 驳回一次就要重排。如果你有明确的参赛或上线截止时间，倒推时至少留出两倍于预期的备案时间。

你现在要做的三个决定

看完这一页，只需要回答三个问题，路径就定下来了。

决定一
这个项目要不要「被搜索到」？
不要→ 走路线 B（H5），今天就能发出去链接
要→ 必须做小程序 + 备案，进入阶段 2
决定二
社区和预约，是 MVP 还是以后再说？
以后说→ 个人主体 + 三页静态版，最快过审
MVP 就要→ 先办个体工商户/企业，再谈开发
决定三
你有明确的截止时间吗？
有→ 今天就去发起备案，因为它最不可控
没有→ 按阶段 1 → 2 → 3 稳步推进
