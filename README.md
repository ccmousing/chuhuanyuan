## 二、为什么原型里的部分效果没法 100% 还原

原型是网页，小程序是另一套渲染体系。差距分两类：

### 已经绕过并还原了的

| 原型的做法 | 小程序里怎么还原 |
|---|---|
| 底部 Tab 的 4 个**内联 SVG 图标** | 小程序原生 tabBar 的图标**必须是图片文件**。改用**自定义 TabBar**（`app.json` 里 `"custom": true`），在 WXSS 里用 **data-URI SVG** 作背景图——用的是原型里同一条 `<path>`，只换了描边色与线宽 |
| 首页**石榴花装饰**（内联 SVG） | WXML 不支持内联 SVG → 用 **5 个圆 + 1 个花心纯 CSS 画**（`.bloom / .petal / .core`），坐标由原型 SVG 的 viewBox 100×100 等比换算成 rpx |
| 红色 / 深色 / 红色渐变**铺到屏幕最顶** | 这 3 页设 `navigationStyle: "custom"`，用 `statusBarHeight`（`app.js` 里统一取一次）做状态栏占位 |
| `grid` 栅格 | WXSS 支持 flex/grid，但这里统一用 flex 以兼容老基础库 |
| 点击分段后**目标闪一下** | 保留：`onSegTap` 里 `setData({ flash: k })`，1.2s 后清除；`@keyframes` 定义在 `culture.wxss` |
| 页内**锚点跳转** | 小程序不用 `offsetTop`，用 `wx.pageScrollTo({ selector: '#ct-2' })`（基础库 2.7.3+） |

### 平台硬限制（无法还原，只能接受）

| 限制 | 表现 | 说明 |
|---|---|---|
| **中文字体只有系统自带的** | iOS 有宋体，**安卓多数机型没有** → 标题会回退成无衬线 | 想两端统一只能内嵌字体文件，很容易超 2MB 上限，一般不做。所以「宋体标题的韵味」只能做到 iOS 好看、安卓普通 |
| **不能用 CSS 变量 `var()`** | 配色全是字面量，改一个色要改多个文件 | 部分安卓机型对 `var()` 支持不稳；要用变量得靠 sass/less 预编译 |
| 不能用内联 SVG | 装饰只能 CSS 画或导出图片 | — |
| 页面高度按内容而非固定 812px | 原型是固定高度的手机画框，真机是全屏自适应 | 这是**正确**的行为，不是缺陷 |
| `position: sticky` 旧基础库不稳 | 文化馆的分段条可能不吸顶 | 若失效，改成 `position: fixed` + 一个等高占位 view |
| 单代码包 ≤ 2MB | 图片不能随便塞 | 图片走对象存储/CDN，或分包 |

### 结论（重要）

**网页版才是观感最好的展示载体**——它固定 375×812、字体统一、装饰完整。
小程序版的价值不是「更好看」，而是「**证明它真的能上架运行**」。

> 对外汇报时的正确用法：用 `prototype.html` 当效果图，用小程序证明可落地。

## 四、每个页面的四个文件

小程序强制要求：**一个页面 = 一个同名文件夹 + 四个同名文件**，缺一跑不起来。

```
pages/index/
├── index.wxml   结构（≈ HTML，但只能用 view / text / image 等组件）
├── index.wxss   样式（≈ CSS，但选择器与单位受限）
├── index.js     逻辑（没有 DOM，一切靠 this.setData() 驱动视图）
└── index.json   页面配置（标题、导航栏样式等）
```

## 五、三条必知规则

1. **页面位置由 `app.json` 的 `pages` 数组决定**，不是文件放哪就自动生效；第一个元素是启动页。
2. **只有 `tabBar.list` 里的页面能用 `wx.switchTab` 跳转**；其它页面用 `wx.navigateTo`。
   本工程里：首页 ↔ 文化 ↔ 体验 ↔ 我的 用 `switchTab`；闯关 / 预约 / 社区 / 祝福卡 用 `navigateTo`。
3. **自定义 TabBar 要在每个 Tab 页的 `onShow` 里同步高亮**，否则切换后底部选中态会错：
   ```js
   onShow() {
     if (typeof this.getTabBar === 'function' && this.getTabBar()) {
       this.getTabBar().setData({ selected: 0 });   // 首页 0 / 文化 1 / 体验 2 / 我的 3
     }
   }
   ```

## 六、从原型翻译的换算规则

| 原型 | 小程序 |
|---|---|
| `div` / `span` / `img` | `view` / `text` / `image`（不能用 div/span） |
| **px × 2** | **rpx**（原型设计宽 375px，小程序 750rpx = 屏宽） |
| CSS 变量 `var(--x)` | 不能用 → 全部字面量颜色 |
| `* { box-sizing: border-box }` | **WXSS 不支持 `*`** → 该行搬不过来，逐个需 `border-box` 的元素单独写（详见第十六节） |
| `querySelector` 改 DOM | 没有 DOM，一律 `this.setData()` |
| `addEventListener('scroll')` | 页面生命周期 `onPageScroll` |
| 手算 `offsetTop` + `scrollTo` | `wx.pageScrollTo({ selector:'#id' })` |
| `[attr="x"]`、`view + view`、`~` | WXSS 不支持这些选择器 → 改用 class |

| 检查项 | 状态 | 修法 |

| 代码包体积 ≤ 2MB | — | 当前 **109.9 KB**（53 个文件），占上限的 5.4% |

> 量体积时注意排除这些**不进代码包**的东西，否则数字会虚高：
> `.git/`（版本库）、`*.md`（已被 `packOptions.ignore` 排除）、`project.private.config.json`（本机配置）。

> 另外已在 `packOptions.ignore` 里显式排除 `.git`、`node_modules` 与私有配置，双保险。

### ⛔ 为什么「组件按需注入」这一项不开（重要，别再改回去）

`app.json` 里加 `"lazyCodeLoading": "requiredComponents"` 的作用是「只注入当前页面用到的自定义组件」，
能减小启动耗时，看起来是个该开的优化。**但本工程用了自定义 TabBar，两者冲突：**

- 按需注入只看各页面 `usingComponents` 里**声明过的**组件；
- 自定义 TabBar 是框架级特性，**不会出现在任何页面的 `usingComponents` 里**；
- 结果：tabBar 不渲染 / `this.getTabBar()` 返回 `null` / 底部四个 Tab 点了没反应。

微信官方社区有两个专帖记录这个问题（2021 年至今，官方建议升 nightly，但多人反馈仍不行）：
- 《微信 lazyCodeLoading 懒加载导致自定义 tabBar 无法展示并抛异常》
- 《"lazyCodeLoading": "" 配置后，自定义 tabBar 无法使用？》—— 里面明确写了「预览和线上都不能显示自定义 tabBar」

**取舍：底部导航能不能用 > 一个性能检查项的勾。** 所以这一项保持未通过，是**有意为之**。
将来真想开，只能把自定义 TabBar 换回原生 TabBar —— 代价是图标必须是 png 图片文件（现在用的是 data-URI SVG，零图片资源）。

> 另外，自定义 TabBar 还有一个硬前提：`app.json` 里 `"custom": true` 之后，
> **所有 tabBar 页面的 json 都必须显式写 `"usingComponents": {}`**（空对象也不能省），
> 否则冷启动时 tabBar 同样渲染不出来。本工程四个 Tab 页都写了。

已在 `project.config.json` 里打开的构建优化：

```json
"setting": {
  "es6": true,        // ES6 转 ES5
  "enhance": true,    // 增强编译
  "postcss": true,    // 样式补全
  "minified": true,   // 代码压缩
  "minifyWXSS": true, // WXSS 压缩
  "minifyWXML": true  // WXML 压缩
}
```

另外用 `packOptions.ignore` 把 `README.md` 排除出代码包（开发文档不需要上传）。

> ⚠️ `setting.urlCheck: false` 是本地开发的「不校验合法域名」开关，**只影响模拟器调试**，
> 不影响提交审核后的实际域名校验——上线仍需在后台配置合法的服务器域名。

## 九、内容与本地数据（补上闭环的三件）

这一节对应交付复盘时发现的**三个真实断点**，均已修复。

### 1. 文章详情页（原来根本不存在）

原来首页「大家都在看」点了会跳到文化馆**顶部** —— 因为没有详情页，`onEntryTap` 只能把它 `switchTab` 到文化 tab。
用户点「为什么出花园要穿红木屐？」，结果落在文化馆第一屏，找不到那篇。

现在新增 `pages/article/article`：首页三条、文化馆「延伸阅读」三条、收藏列表都能直接打开文章。

**关键设计：内容与页面解耦。** 新增 `utils/content.js` 只存数据，页面只认 `id`：

```js
{ id: 'why-clogs', tag: '符号', icon: '🪵',
  title: '为什么出花园要穿红木屐？', sub: '一个状元传说，和一双会响的鞋',
  needVerify: true,
  paras: ['……', '……'] }
```

以后扩写正文（P1）**只改 content.js，不用动任何页面代码**。
`needVerify: true` 的文章，详情页会自动显示「内容提示」块，提醒需经审校。

> ⚠️ 正文目前是**精简版**（每篇 3–5 段，够跑通详情页与验证排版）。
> 完整扩写与民俗审校属于 P1，尚未做。
> **内容分级（青少年版 / 成人版）已决策不做** —— 分级要有两版正文才成立，而正文本身还没扩写。
> 相应地，闯关页顶部原本那个「青少年版」标签已移除：只有一版内容时它暗示存在另一版可选，属于不实标注。

### 2. 本地存储（原来 `wx.setStorage` 使用次数 = 0）

新增 `utils/store.js` 统一封装：

| 数据 | 存储键 | 谁在写 | 谁在读 |
|---|---|---|---|
| 仪式进度 | `ritualStep` | 体验页 | 我的花园 |
| 答题记录 | `quiz` | 闯关页 | 我的花园 |
| 收藏 | `favorites` | 文章页 | 我的收藏页 / 我的花园 |
| 徽章 | `badges` | 体验页 / 闯关页 / 文章页 | 我的花园 |
| 阅读记录 | `readIds` | 文章页 | 我的花园 |
| 祝福卡张数 | `cardCount` | 祝福卡页 | 我的花园 |
| 昵称 / 年份 | `profile` | 我的花园 | 我的花园 |

三个设计点，都不是可有可无的：

1. **key 带版本号**（`chy_v1`）。以后改数据结构只升版本号，旧数据自动作废，不会因为读到旧结构而白屏。
2. **`try/catch` 包住所有读写**。`wx.setStorageSync` 在存储空间满或被系统禁用时会**直接抛异常**，裸调用会让整个页面逻辑中断。
3. **所有读操作都有默认值兜底**，页面不需要写判空。

**「我的花园」现在全部是真实数字**：仪式进度、徽章解锁状态（未解锁的显示解锁条件）、收藏篇数、答题正确率、已生成卡数。原来写死的 7 / 3 / 12 已删除。

### 3. 分享带参数（原来 8 个分享的 path 全是首页）

原来的问题：分享出去的祝福卡、文章、闯关结果，对方点开都只是首页。

**这里有一个微信的坑值得记住**：`onShareAppMessage` 返回的 `path` 若指向 **tabBar 页面，query 参数会被忽略** —— 因为 tabBar 页只能用 `switchTab` 打开，而 `switchTab` 不支持带参数。

所以分工是：

| 页面 | 是 tabBar 页？ | 分享 path |
|---|---|---|
| 文章详情 | 否 | `/pages/article/article?id=xxx` ✅ 有效 |
| 祝福卡 | 否 | `/pages/blessing/blessing?tpl=2` ✅ 有效 |
| 知识闯关 | 否 | `/pages/quiz/quiz?from=share` ✅ 有效 |
| 首页 / 文化 / 体验 / 我的 | **是** | 只能落到首页，参数无效 ⚠️ |

**结论：需要「分享到具体内容」的功能，落地页必须设计成非 tabBar 页面。**
这是要在设计阶段就定下来的事，不是写完再改 —— 记在这里免得下次踩。

另外：祝福卡的分享 path **刻意不包含名字**。姓名属个人信息，不写进可被转发出去的链接。

### 4. 顺带清理掉的假数据

| 位置 | 原来 | 现在 |
|---|---|---|
| 首页三篇文章 | 「4.2 万阅读」等编造数字 | 换成内容简介 |
| 社区横幅 | 「1,286 位潮汕人…」 | 「该板块规划在 V2 · 需完成内容安全与举报机制」 |
| 我的花园 | 写死 7 / 3 / 12 | 全部读本机存储 |
| 预约 / 社区菜单项 | 「1 条进行中」「18」 | 如实标注「V2 · 需个体工商户主体」并说明原因 |
| 儿童资料 | 写死「阿澄 · 2009 年生 · 汕头」 | 用户自己填昵称；且**不收集**手机号、真实姓名、位置 |

**原则：界面上不出现编造的数据。** 演示数据要标出来；别人的、编的数字一律不放。

```bash
node tools/check-wxss.js        # WXSS 类名一致性 —— 样式漏写 / 孤儿样式检查
node tools/check-copy.js        # 内容约束 —— 文案断行 / 题量 / 篇幅 / markdown 残留
```

三个脚本都在**工程外**（`chuhuayuan/tools/`），不会打进代码包。

**`verify-store.js`** —— 用内存替身模拟 `wx.getStorageSync` / `wx.setStorageSync`：

| 组 | 覆盖 |
|---|---|
| A | 内容库：按 id 取文章、按序取列表、过滤无效 id |
| B | 空存储下的全部默认值 |
| C–I | 仪式进度（含归零）、答题累加、收藏反复切换、徽章只解锁一次、阅读去重、资料字段合并、卡片计数 |
| **J** | **异常降级**：让 `setStorageSync` 抛异常，确认不会把异常抛给调用方（页面不崩） |
| K | 一键清除后全部回到默认值，存储 key 已移除 |

**`verify-flow.js`** —— 更进一步：把 `wx` / `Page` / `getApp` 全部替身掉，**直接加载真实的页面 js**，
实例化后调用页面的生命周期与事件函数，验证「页面有没有正确调用存储」。
单元测试只测得到 store，测不到页面有没有真的用它 —— 这一层补的就是这个缺口。

它按页面分组跑：文章详情（取数 / 收藏 / 无效 id / 延伸阅读不含自己）、收藏页（空态切换 / 取消收藏）、
仪式页（进度落盘 / 徽章时机 / 恢复上次进度 / 重新开始 / 最后一步跳转）、闯关页（防重复作答 / 结果页 / 累计成绩跨轮次）、
我的花园（所有数字与存储一致 / 一键清除）、首页（三条文章都指向真实文章 / 三种跳转方式）、文化馆（延伸阅读与首页不重复）。

> 还测出过一个真 bug：**原来只要打开一次「体验」页，就会把进度写进存储**，
> 于是「我的花园」显示 1/7 —— 而用户一步都没走。这是被 `verify-flow.js` 抓出来的，
> 修法是「页面打开不写进度，只有点击前进才写」，另给 `store` 加了 `resetRitual()` 让「重新走一遍」真正归零。

### 内容模块的组织：内容与页面解耦

`utils/` 下有三个**纯数据模块**，页面只引用、不定义内容：

| 模块 | 内容 | 谁在用 |
|---|---|---|
| `content.js` | 6 篇文章（4428 字，`sections` 结构）+ 4 个徽章 | `article` / `index` / `culture` / `favorites` |
| `quiz-bank.js` | 30 题（入门/进阶/挑战各 10）+ 每轮抽题逻辑 | `quiz` |
| `blessing-copy.js` | 12 条祝福卡文案（含预设断行 `lines`） | `blessing` |

**为什么值得单独抽出来**（不只是「看起来整洁」）：

1. **改内容不用碰页面代码** —— 加一道题、改一句文案只动数据文件，页面逻辑零改动，回归风险小。
2. **能被工具直接校验** —— 三个模块都是纯数据、不依赖 `Page()`，所以 `tools/check-copy.js` 可以 `require` 它们，
   把「断行超宽」「题量不足」「`art` 指向不存在的文章」「正文混进 markdown」这些
   **在小程序里不会报错、只会静默出错**的问题自动查出来。
3. **职责清晰** —— 页面管流程与展示，数据管内容。

⚠️ 由此有一条纪律：**不要把内容写回页面 js**。写回之后第 2 条就失效了 —— 校验脚本再也读不到它。


## 十、祝福卡实现说明（canvas 导出图片）

这是 MVP 唯一自带传播属性的功能，已完整实现。数据流：

```
选模板 / 填名字 → 点「生成」→ 取 canvas 节点 → 绘制卡片
   → canvasToTempFilePath 导出临时图片 → 页内展示 + 保存相册 / 分享给好友
```

### 排版：预设断行（关键设计，别改回去）

每句祝福在 `templates` 里存**两个字段**：

```js
{ t:   '红木屐踏过门槛，愿你走到哪，都记得从哪出发。',   // 列表里显示的整句
  lines: ['红木屐踏过门槛，', '愿你走到哪，都记得从哪出发。'] }  // 卡片上的断行
```

- 页内预览用 `lines` 逐行渲染，canvas 也读同一套 `lines` → **两端排版完全一致**
- 好处：避免自动折行产生**孤字行**（原来会折成「…都记得 / 从哪出发。」），
  也避免预览和导出图长得不一样
- `wrapText()` 仅作兜底：万一某行仍超宽才再切一次

**约束**：canvas 画布 600px 宽、左右各留 48px → 可用 504px，
正文 34px → **单行最多 14 个中文字**。新增文案时务必按这个上限断行，否则会触发兜底折行。

页内预览是**竖版卡片**（固定 800rpx 高），分三层次：顶部引导语「潮汕 · 成人礼」→
中部正文（垂直居中）+ 署名 → 底部（分隔线 + 品牌 + 落款日期），右上角有石榴花装饰。
这样它看起来是「一张卡」，而不是一块色块。

### 五个容易踩的点

1. **canvas 2d 必须成对配置**：WXML 里写 `type="2d"`，`canvasToTempFilePath` 里**传 `canvas` 实例**——
   不能再像老接口那样传 `canvasId`，否则导出失败。
2. **高清导出**：`canvas.width/height = CSS 尺寸 × dpr`，再 `ctx.scale(dpr, dpr)`，
   导出时 `destWidth = CSS 尺寸 × dpr`。不做这一步图会糊。
3. **canvas 没有 `letter-spacing`**：品牌字「出花園 · 潮汕成人礼」的字间距要**逐字绘制**手动实现（见 `drawSpaced`）。
4. **折行自己算**：用 `ctx.measureText` 逐字累加判断是否超宽（见 `wrapText`）。中文按字断行即可。
5. **圆角矩形手写**：用 `ctx.arcTo` 拼（见 `roundRect`），不用 `ctx.roundRect`（兼容性更稳）。

### 离屏画布放哪

`.canvas-holder` 用 `position: fixed; left: -9999px`，不占布局也不显示。
**若某些机型导出是空白图**，把它改成 `left: 0; top: 0; opacity: 0;` 再试。

### ⚠️ 保存到相册是「隐私接口」，必须两步都做

1. **后台配置**：在小程序后台 →「设置 → 服务内容声明 → 用户隐私保护指引」里，
   声明 **相册（仅写入）权限**。没声明会被驳回。
2. **代码里先要授权**：先 `wx.requirePrivacyAuthorize()` 确认用户同意隐私协议，
   再 `wx.saveImageToPhotosAlbum()`；被拒绝时用 `wx.openSetting()` 引导用户手动开启。

分享给好友用 `wx.showShareImageMenu`（基础库 2.14.4+）；低版本已降级为放大预览 + 提示长按。

## 十一、出花园吉日：为什么用日期表而不是「农历库」

首页倒计时读的是 `utils/lunar.js`，它只做一件事：**算出下一个农历七月初七（出花园正日）是哪天**。

### 设计取舍（这是有意的，不是偷懒）

| 方案 | 问题 |
|---|---|
| 内置 1900–2100 农历数据表（约 200 个十六进制魔数） | 支持任意农历换算，但**这份数据在本项目内无法被独立校验**。一旦有一个常量抄错，错误会静默传播，而且错的那一年往往要到那年才暴露 |
| **逐年核对过的七夕公历日期表（本项目采用）** | 每一行都可回溯核对（`DATA_SOURCES` 里存了 3 个来源）；完全离线、零依赖；45 行覆盖 2005–2049 |

**关键点：宁可选择可被验证的方案，也不选看起来更强但无法验证的方案。**

### 自动校验（改了日期表一定要跑）

```bash
cd ..            # 到 chuhuayuan/
node tools/verify-qixi.js
```

校验脚本在**工程外**（`chuhuayuan/tools/`），不会打进代码包。它跑 5 组检查：

| 检查 | 说明 |
|---|---|
| A. 与第二来源逐行对照 | 12 个年份与 rili.com.cn 公开列表比对（与主来源分属不同站点） |
| B. 覆盖范围与连续性 | 年份必须连续、与 `QIXI_RANGE` 一致 |
| **C. 农历年长约束** | 相邻两年七夕间隔**只能是 354 / 355 / 383 / 384 天**（农历平年 354–355 天、闰年 383–384 天）。**这是最强的一条**——任何一处抄写错误几乎必然破坏它 |
| D. 落点范围 | 七夕只可能落在 7月20日–9月5日 |
| E. 行为测试 | 七夕前 / 当天 / 次日 / 当年已过 / 跨年 / 超范围共 6 个用例 |

### 超出覆盖范围会怎样

`nextChuHuaYuan()` 返回 `null`，首页**不显示天数**（显示「—」），底部提示「日期表覆盖 2005–2049 年，请更新 utils/lunar.js」。
——**宁可显示"没有"，也不显示一个算错的日子。**

### 怎么续期

在 2049 年到之前，往 `QIXI_TABLE` 里补下一年的 `年份: [月, 日]`，然后跑校验脚本。
建议提前补到 2059 年（农历数据在历年公开日历中均可查）。

## 十五、「点击没反应」怎么查（按顺序）

小程序最麻烦的一点：很多问题**不报错也不打日志**，表现就是「点了没反应」。按这个顺序查，能覆盖绝大多数情况。

### 第 1 步：确认改动真的生效了

- 点开发者工具的「**编译**」（不是刷新）。**改了 `app.json`（尤其是增删页面）必须重新编译。**
- 看工具里的**基础库版本**，建议 ≥ 2.20.1（`wx.getWindowInfo` 需要 2.20.1+，本工程写了降级，但版本太老还会有别的问题）。

### 第 2 步：看 Console 有没有红字

打开「调试器 → Console」。有报错先解决报错 —— **页面 js 一旦在模块层抛错，整页所有点击都会失效**（页面根本没注册成功）。

### 第 3 步：对照这张表

| 症状 | 最可能的原因 | 修法 |
|---|---|---|
| **底部四个 Tab 空白 / 点了没反应** | ⛔ `app.json` 里有 `lazyCodeLoading: "requiredComponents"`，与自定义 TabBar 冲突 | 删掉那一行（本工程已删，**别再加回去**，理由见第八节）|
| **页面内容正常，但底部 Tab 不显示** | 某个 Tab 页的 json 少了 `usingComponents: {}` | 四个 Tab 页都要写（空对象也不能省）|
| **某个按钮点了完全没反应** | WXML 里 `bindtap` 的方法名在 js 里不存在或拼错 | 对照方法名字符串逐个核 |
| **点了有反应，但看不到变化** | 提示是短时 `showToast`；或跳的目标就是当前所在 Tab | 加长 duration；确认目标不同 |
| **点了弹「该功能未开放」** | **设计如此** —— 预约 / 社区属个人主体不开放的类目 | 不是 bug |
| **整页点不动，连滚动也不行** | 有全屏透明元素盖在上面 | 搜 `position: fixed`，检查有没有没设 `pointer-events: none` 的遮罩 |
| **真机能点、模拟器不能点（或反之）** | 基础库版本差异 / 工具缓存 | 「清缓存 → 全部清除」后重新编译 |

### 第 4 步：用「编译模式」直达目标页（最快的一招）

工具的**「编译模式」**可以指定启动页面和启动参数。要单独调试文章页，就加一个编译模式：
启动页填 `pages/article/article`，启动参数填 `id=why-clogs`。

比一层层点进去快得多，也顺便排除了「是不是跳转那一步坏了」。

### 本工程「点击没反应」的历史病例

| 症状 | 根因 | 修法 |
|---|---|---|
| 底部四个 Tab 点了没反应 | 为了过「组件按需注入」检查项加了 `lazyCodeLoading: "requiredComponents"`，与自定义 TabBar 冲突 | 删掉该配置；在第八节和 `custom-tab-bar/index.js` 里写明原因 |
| 打开「体验」页什么都没做，「我的花园」就显示 1/7 | `ritual.js` 的 `onLoad` 里写了「首次进入就把进度写成 0」 | 改成「打开页面不写进度，只有点击前进才写」 |

**共同点值得记一下：两个 bug 都不是「代码写错了」，而是「加了一个看起来合理的优化 / 默认行为，但它和这个平台的其他机制冲突」。**
所以对「优化配置项」要格外小心 —— 开之前先想清楚它和现有机制（尤其是自定义 TabBar、自定义导航栏）有没有交互。

## 十六、样式陷阱：盒子模型（`box-sizing`）

### 症状：按钮比卡片宽出一条，右边像被切掉了

原理：**`width: 100%` 只约束「内容盒」**。如果没写 `box-sizing: border-box`，
元素实际占的宽度 = 容器宽 + 左右 padding + 左右 border。

### 根因：原型的全局重置搬不过来

原型 `assets/styles.css` 第 34 行有一句：

```css
* { box-sizing: border-box; }     /* 原型里所有元素 = border-box */
```

**但 WXSS 不支持 `*` 通配符选择器**（官方「选择器」列表里只有 `.class` / `#id` / `element` /
`element, element` / `::after` / `::before`，没有 `*`）。

所以这行在翻译时**静默消失**了 —— 原型里所有元素都是 `border-box`，到了 WXSS 全部退回默认的
`content-box`。凡是「写了宽度 + 有 padding」的元素都会变宽，`.btnL` 正好是这种写法，
于是成了唯一的受害者。

**这是 HTML 原型 → WXSS 移植的一类系统性风险**：网页侧靠全局 reset 兜住的东西，
WXSS 侧没有兜底，而且**不报任何错**，只表现为"尺寸不对"。

> 想恢复全局效果，只能用 WXSS 支持的选择器逐个写：
> ```css
> view, text, image, button, input, textarea, scroll-view { box-sizing: border-box; }
> ```
> ⚠️ **但本工程不能这样做** —— 见本节末尾 `.tabbar` 那个例外：它**故意**依赖 `content-box`
> 让安全区补在白条下方，加了全局 border-box 会把图标区压扁。所以本工程采用的是**逐条精确修**。

本工程真实踩过（已修）：

```css
/* ✗ 修复前 */
.btnL { width: 100%; padding: 26rpx; }
/*   实际宽度 = 686 + 26×2 = 738rpx → 比卡片宽 52rpx，最右 20rpx 跑到屏幕外被裁掉 */

/* ✓ 修复后 */
.btnL { width: 100%; padding: 26rpx; box-sizing: border-box; }
/*   实际宽度 = 686rpx，与卡片左右对齐 */
```

**为什么影响面很大**：`.btnL` 是全站主按钮类（祝福卡的生成/保存/分享、闯关的下一题与结果页、
文章页的返回首页、收藏页的去文化馆……都走它）。**改一处即全站生效** —— 这也是为什么
按钮这类公共样式一定要放 `app.wxss` 统一定义，而不是各页面各写一份。

⚠️ 同一个类在不同父容器里表现不同：`.btnL` 在「体验」页的「上一步 / 下一步」上看不出问题，
因为它们在 `display: flex` 的 `.row` 里，`flex: 1` 让 `flex-basis: 0%` 接管主轴尺寸，
`width: 100%` 被忽略。**所以别因为"某处看着正常"就放过这类 bug。**

### 怎么自动发现

```bash
cd ..                    # 到 chuhuayuan/
node tools/check-layout.js
```

扫描所有 WXSS，找「百分比宽度 + 左右内边距/边框 + 缺 `box-sizing`」的规则，并算出会溢出多少 rpx。
本工程当前输出 **无 ✅**。

> 写这个脚本时又踩了一个坑，值得记：第一版**忘了先把注释整体剥掉再解析**，
> 结果注释里那句「注释中含 `width:100%`」的半角冒号被当成了声明分隔符，
> 把紧随其后的 `box-sizing` 吞进了注释的值里 —— **脚本误报了**。
> 教训：解析 CSS 前必须先剥注释，且改完脚本要拿"故意写坏的版本"反向验证一次。

### 已知的「故意不写 border-box」

`.tabbar` 用 `height: 116rpx` + `padding-bottom: env(safe-area-inset-bottom)`。
这里**恰恰**要靠内容盒把图标区固定在 116rpx 内、让安全区补在白条下方 —— **不要给它加 `border-box`**。
所以脚本把「固定高度 + 上下内边距」这类单独列成 ⚠️ 提示，不直接判错。

### 处理口径：如实标注，而不是补个假功能

这两页最容易走错的方向是「让它看起来能用」——加个弹 toast 的按钮，或者把 UI 做得更完整。
但演示时**「点了没反应」比「明确说规划中」更难看**，而「有假数据支撑的完整 UI」最糟：
评审或老师问一句「这个预约是真的能约吗」，就下不来台。

所以统一走这套：

| 位置 | 做法 |
|---|---|
| 页面顶部 | `.plan-bar` 说明条：讲清**为什么未开放**，以及下方内容是界面示意 |
| 原「预约 / 报名」「点赞 / 评论 / 分享」按钮 | 改 `.go-plan` / `.acts-plan` **灰显**，文案写「规划中」，`bindtap` 弹一段如实说明 |
| 首页四宫格入口 | 该入口的图标转灰 + 名称下加「规划中」小标，**进去之前就知道** |

### 一条容易忽略的原则：浏览 ≠ 交易

**不是所有交互都要一并灰掉。** 分类 chip 的切换、帖子列表的滚动是**浏览行为**，
不构成任何承诺，保留交互反而更自然。真正需要拦住的是**会让用户以为"能办成事"的动作**——
提交预约、发布内容、点赞。

判断标准一句话：**这个点击有没有向用户承诺一件我做不到的事？**

### 自动化检查：`tools/check-bind.js`

本次问题的来源是「按钮有样式但没绑事件」，肉眼很难扫干净，所以固化成脚本：

```bash
cd ..                         # 到 chuhuayuan/
node tools/check-bind.js
```

- **A 组（严格，会失败）**：WXML 里 `bind*` / `catch*` 绑定的方法必须在同名 js 里存在。
  防的是「方法改名了但模板没改」——这种错小程序**不报错**，只是点了没反应。
- **B 组（启发式，仅提示）**：找出 class 像按钮（`btn` / `go` / `entry` / `chip` / `opt` 等）
  但没绑事件的 `<view>`。靠命名猜测，必然有误报（容器元素会被误抓），人工过一遍即可。

> 本工程 B 组的 2 条提示都是**容器**（`.result-btns`、`.acts-plan`），里面每个子按钮各自绑了事件 —— 属正常。
> **不要为了让提示消失而给容器硬加事件。**

**写脚本时踩的坑**：块注释里写了 `bind*/catch*`，那个 `*/` 把注释**提前结束了**，导致后面的文字变成代码、直接语法错误。
**块注释内不能出现 `*/`** —— 这类"注释里的特殊字符"问题，本工程已经踩过两次（另一次是 CSS 注释没剥干净导致误报）。

### 验证这类改动干不干净：`tools/check-wxss.js`

「删掉一个标签」这类改动最容易留下半截活，两种都肉眼扫不出来：

- **样式漏写**：WXML 用了新 class，但 wxss 里没定义 → 元素以无样式状态渲染
- **孤儿样式**：WXML 删了那段结构，wxss 里的 class 还留着 → 越积越多，久了没人敢删

```bash
cd ..                         # 到 chuhuayuan/
node tools/check-wxss.js
```

| 组 | 检查 | 强度 |
|---|---|---|
| A | WXML 用到的 class 必须在「本页 wxss + app.wxss」里有定义 | 严格（会失败） |
| B | 本页 wxss 定义了、但 wxml 没用到的 class | 提示（可能是动态类名或预留状态） |

**实现上踩了两个坑，都值得记**：

1. **解析前必须先剥注释** —— 这个坑本工程踩了**第三次**了。
   WXSS 注释里为了说明「为什么不再有某个类」，往往会写出类名，
   不剥注释就会把它当成孤儿样式误报。
2. **`class` 里的三目表达式，字符串不一定是类名**。本工程的真实例子：

   ```html
   <view class="quote serif {{flash === 'ct-1' ? 'flash' : ''}}">
   ```

   这里的 `'ct-1'` 是 **id 值**，不是类名，会被误报成「样式未定义」。
   解法：先收集本文件 `id` 与 `data-*` 的静态值，命中这些值的三目字符串一律不当作类名。
3. `class="{{a ? 'ok' : 'no'}}"` 里的 `ok` / `no` **确实是类名**，不能一并过滤掉 ——
   所以处理方式是「提取三目字符串 + 排除 id/data 值」，而不是「忽略动态类名」。

两个组都做过**反向验证**：故意注入一个未定义的类和一个孤儿类，A / B 两组都能报出来。

> 顺便说明 B 组的刻意设计：**全局类不计入孤儿**。`app.wxss` 里的 `.btnL` / `.box` / `.hd`
> 本来就是给多个页面复用的，某一页没用上很正常，不该报。
